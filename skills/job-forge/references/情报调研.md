# M4 · 面经与舆情情报

> ASu 完全没有这一层：它的调研对象是「你的简历」和「JD」，不研究「对方公司到底怎么考」。
> 本层补的正是面试当天最实用的信息：几轮、每轮问什么、考官偏好、团队真实状态。

## 分层来源（按可信度，不按方便度）

| 优先级 | 来源 | 能拿到什么 | 注意 |
|---|---|---|---|
| 1 | 小红书 | 真实面经、踩坑、团队氛围、HR 风格 | 广告与培训机构帖多，看评论区交叉验证 |
| 2 | 牛客 | 技术岗完整题面、流程轮次、时间线 | AI 岗题面质量最高 |
| 3 | 脉脉 | 组织状态、业务线调整、汇报关系、槽点 | 情绪化严重，只取事实，不取评价 |
| 4 | 搜索引擎 / 官网 | 公司背景、产品、融资、近期动态 | **只能作补充，不能当面经用** |

## 三档调研深度

| 档 | 对应速度档 | 做什么 | 耗时 |
|---|---|---|---|
| 轻量 | 速准 | `[公司] [岗位] 面经` 取前 3 条 → 5 行公司速览 + 3 条高频题 | 3 分钟 |
| 标准 | 标准 | 四维（背景/产品/竞品/氛围）+ 面经 5–8 条 + 风格总结 | 20 分钟 |
| 深研 | 深研 | 加竞品对比、10 条反问、3–5 篇延伸阅读 | 40 分钟 |

## 搜索式（照抄改名字）

| 维度 | 搜索式 | 提炼 |
|---|---|---|
| 公司背景 | `[公司] 融资 创始人` | 阶段、核心团队、活下去的概率 |
| 产品定位 | `[产品] 官网`、应用商店 | 核心功能、目标用户、差异化 |
| 近期动态 | `[公司] site:36kr.com` | 战略调整、产品线裁撤、扩招/裁员 |
| 竞品格局 | `[产品] 竞品 对比` | 主要对手、自己的位置 |
| 团队氛围 | `[公司] 脉脉 面试体验` | 轮次、氛围、真实槽点 |
| 面经 | `[公司] [岗位] 面经`、`[岗位] 面经 2025 OR 2026` | 题目、考点、流程 |

## AI 岗专项搜索词

```
[公司] AI 应用 面经
[公司] 大模型 面试 几轮
[公司] RAG 面试题
[公司] Agent 岗 面试
[公司] 算法/应用 区别 面试   ← 判断这个岗位实际在做什么
```

**最后一条最有用**：很多公司的"AI 岗"实际是"会调 API 的业务开发"，也可能是"要发论文的研究岗"。提前分清，能避免整场面试错位。

## 输出规范（不许打折）

1. **每条外部信息必须带真实 URL**：`（来源：[标题](URL)）`
2. 只有摘要没有原文 → 标注「基于搜索摘要，未验证原文」
3. 找不到就删掉这条，不要"合理推测"
4. 面经极少时可用同赛道公司替代，**必须注明是替代**

## 面试风格总结模板（3–5 句）

```
共 __ 轮：__ → __ → __。
每轮侧重：一面考 __，二面考 __，终面考 __。
考官偏好：__（如"爱问口径，必追分母""会让你现场算""喜欢追问失败案例"）。
特别提示：__（如"会现场看代码""会问上一份工作为什么离职""压力面风格明显"）。
```

## 情报怎么反哺其他段

| 情报发现 | 反哺动作 |
|---|---|
| 必考 RAG 评测口径 | 把对应 Claim 的 `interview_details` 补到 L2（主档 P1） |
| 会现场看代码 | 走 ASu `project-guide` 补源码证据索引 |
| 团队在收缩/换 leader | 回 M1 重估 P0，必要时放弃 |
| 面试官是业务方不是技术方 | 调整口播比例：少讲实现，多讲业务价值 |
| 会问离职原因 | 预写 3 版答案（诚实版 / 中性版 / 一句话版），进 P4 |
