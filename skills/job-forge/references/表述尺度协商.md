# 表述尺度协商（S2 增强）

> 目的：在**不虚构事实**的前提下，把同一段真实经历写到它最强的合法形态。
> 一句话：**尺度 = 表述强度 ÷ 追问承压能力**，不是"造假程度"。

---

## 0 前提：这份文档不做什么

它**不**提供"把不存在的技术栈/指标/项目写上去，反正背调查不到"的做法。原因见 §6（这是成本问题，不只是道德问题）。

它做的是：真实事实有多少种合法表述、每种表述的强度与代价、以及怎么和用户逐条谈定。

---

## 1 三条不可协商（事实层）

这三层一旦松动，整份简历就是负债。

| 维度 | 允许的做法 | 禁止的做法 |
|---|---|---|
| **技术栈** | 写用过的；写"有可迁移经验（从 X 迁移到 Y）"并说明迁移点；写"了解"且能答定义与边界 | 把没用过的框架写成项目里的技术栈；把教程跟练写成生产使用；把"看过文档"写成"熟练" |
| **量化指标** | 四种合法替代：①定性结果（"消除人工合并步骤"）②区间 + 口径（"5–8 分钟，200 行量级，单机"）③测量计划（"拟用 200 条标注集评估 top5 召回"）④相对变化（仅在真做过 A/B 或前后对比时） | 编造百分比、用户量、延迟、准确率、GMV；把估算写成实测；把行业均值挪成自己的数据；不写分母/周期/环境 |
| **项目事实** | 写真实规模与真实阶段；未上线写"原型/技术验证"；内部试点写"内部试点" | 虚构用户数、团队人数、预算、上线状态；把 demo 写成生产系统；把别人的项目写成自己主导 |

**归属也不可协商**：团队做的、平台/框架提供的、AI 生成的，必须与"我做的"分列。这不是谦虚，是防守——面试官最常问的就是边界。

---

## 2 可协商的四层（表述层）

真正能谈的只有这四样，全部在事实之内：

| 层 | 可调范围 | 判定标准 |
|---|---|---|
| **1 动词强度** | 参与 → 负责 → 主导 | 与该事实对应的决策权一致。有决策权才能用"主导" |
| **2 抽象层级** | 实现名 → 通用能力名 | 越抽象越专业（`RunManager` → "可扩展编排"），且不损失真实性 |
| **3 口径选择** | 同一事实的多种合法表述中选最有利的 | 三个口径都真，只是重心不同 |
| **4 取舍排序** | 写什么 / 先写什么 / 不写什么 | 省略 ≠ 造假。相关性低的可以不写 |

---

## 3 三档模板（逐条生成，让用户选）

以"用 AI 生成脚本合并会议表格"为例：

| 档 | 表述 | 强度 | 代价（追问承压） |
|---|---|---|---|
| **A 保守** | 编写脚本合并多场会议表格，减少人工整理时间 | 低 | 任何追问都能答 |
| **B 标准** | 设计字段映射与联合主键规则，用 AI 生成脚本并迭代修正；单次合并从约 2 小时降至 5 分钟内（本人单机 3 次实测） | 中 | 需答得出"口径/样本/环境" |
| **C 进取** | 识别出人工合并的错合并风险（同名专家跨场次），设计"会议+日期"联合主键驱动脚本迭代，把单次处理压缩到 5 分钟内（200 行量级，本人实测 3 次） | 高 | 需答得出"换人是否仍 5 分钟/扩 10 倍先崩哪" |

三档的共同点：**每一句都能被证明**。区别只在"用掉多少事实余量"。

判断是否越界：把 C 档拿去问三个问题——
1. 这个动作是你做的吗？（归属）
2. 这个数字有分母和样本吗？（口径）
3. 换个环境还成立吗？（外推）

三个都答得出 → C 合法。答不出任一 → 降档，不要改措辞硬撑。

## 4 交互流程（四步，逐条谈）

### Step 1 锁事实基线
先跑账本（`求职主档 P1`），每条 claim 的锚点钉死：PR 链接、源码路径、日志、对话记录。
**这一步不协商。** 没有锚点的条目直接进"待补证据"，不进表述环节。

### Step 2 三档并排
对每条要上简历的 claim，一次性给 A/B/C 三档 + 每档的"追问代价"。呈现成表，不让用户凭空说"我要多美化"。

### Step 3 选档 + 即时压测
用户选完后，对选了 C 的条目**立刻**跑两轮追问：

```
L1（事实层）：这个数字的分母是什么？样本几次？什么环境？
L2（判断层）：换个人用还成立吗？规模扩 10 倍先崩哪？重做你会改什么？
```

答不出 → 自动降档，并记录"为什么降"。**压测不过就不许用这一档**——这是唯一的硬闸门。

### Step 4 出稿 + 追问预案卡
每条最终表述旁边附一张卡：

```
表述：<最终那一句>
锚点：<PR / 路径 / 日志>
可答：L1 □  L2 □
已知薄弱点：<例如"换人可用性未验证">
被问到时怎么讲：<承认 + 给出验证思路>
```

## 5 红线自检（出稿前四项扫描）

| 扫描项 | 通过条件 | 不通过时 |
|---|---|---|
| 技术栈 | 每个技术名都能指到一个锚点（仓库/PR/文件） | 删除，或标注"可迁移/了解" |
| 数字 | 每个数字都有分母 + 周期 + 环境 | 改为区间/定性/测量计划 |
| 规模与阶段 | 与账本的交付阶段一致（原型≠上线） | 改阶段词，不改数字大小 |
| 归属 | "我做的 / 团队 / 平台 / AI 生成"已分列 | 补边界，或降动词强度 |

四项任一不通过 → 该条不进入正式稿（可留在内部草稿）。

## 6 为什么"写点查不到的"是劣势策略

给用户算一笔账，比讲道理有用：

| 成本项 | 现实情况 |
|---|---|
| **第二层追问** | AI 岗几乎必问"这块代码你写的吗？能打开看看吗？"——吹的部分在 L2 必崩，而 L1 崩了还能救，L2 崩了这轮就结束 |
| **交叉验证** | 同一公司的两个面试官会对照你的说法；技术面与 HR 面都会问同一段经历 |
| **背调与试用期** | 学历、任职时间、职级可查；技术能力在试用期第一周就暴露。代价不是"面试失败"，是**已入职后被解除** |
| **概率账** | 吹一条只提升一点点过筛率，但被拆穿一次，整场面试的可信度归零——期望值为负 |

反过来，**具体、有锚点、边界清楚的表述在 AI 岗更吃香**：面试官对"你当时为什么这么切分"的兴趣，远大于对"你提升了 30%"的兴趣。

## 7 竞争力到底从哪来（不用吹的六条）

1. **相关性密度**：每一行都对着 JD 的要求写；不相关的经历删掉比留着强
2. **具体性**：对象 + 动作 + 约束 + 取舍。具体细节的记忆度远高于形容词
3. **结构可扫**：`**通用支柱名：**` 开头，6 秒能扫到能力关键词（HR 初筛平均就是这个时长）
4. **可验证锚点**：GitHub / PR / 文档链接直接放。**可验证本身就是竞争力**——大多数候选人不敢放
5. **转行因果链**：说清旧经历怎么迁移（会议统筹 → 多方干系人交付 + 非结构化信息处理），这比硬凑 AI 项目更有说服力
6. **一句话匹配叙事**：把"为什么我是这个岗位的最优解"压成一句，放进摘要与自我介绍开头

这六条都不需要虚构，而且比虚构更抗追问。
