| # | 主张（claim） | 证据来源 | 状态 | interview_details 能否答 L2 | 适用岗位 |
|---|---|---|---|---|---|
| 1 | | PR链接 / 源码路径 / 日志 | 已确认 / 待确认 / 已过期 / 不采用 | 能 / 不能 | |

**状态直接用 ASu 四态**，不另立词表：
- `已确认` → 可进正式简历
- `待确认` → 只进内部草稿，导出 PDF 前必须确认或删除
- `已过期` → 时间敏感（在读年级、论文状态、Star 数）需更新
- `不采用` → 不准确或不公开，保留原因便于复盘

**本层门槛（ASu 没有的一条）**：进 `interview` 之前，每个 `已确认` 主张的 `interview_details` 必须能答到第二层（换方案会怎样 / 失败路径 / 扩 10 倍先崩哪 / 重做改什么）。答不出 → 回 `project-guide` 补机制，或降级为 `待确认`。

## 为什么主档不重造账本

ASu 的账本是 JSON + 校验器（`~/.workbuddy/asu-skills/scripts/validate_claim_ledger.py`），能机器校验状态矛盾。
若主档再抄一份 markdown 版，必然出现"两边各改一处"。
所以：**事实存账本，状态看主档索引，两者靠 `claim` 字段对齐。**
