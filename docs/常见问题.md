# 常见问题（FAQ）

## 安装与兼容

### Q1 装了但技能不出现 / 不触发

按顺序排查：

1. **没重启**。技能列表在 runtime 启动时读取，装完必须重启或新开会话。
2. **frontmatter 缺字段**。`SKILL.md` 顶部必须有 `name` 与 `description`，缺任一个都不会被识别。
   ```bash
   head -5 <skills-dir>/job-forge/SKILL.md
   ```
3. **目录层级错**。必须是 `<skills-dir>/job-forge/SKILL.md`，不能是 `<skills-dir>/job-forge/job-forge/SKILL.md`。
4. **被手动档关掉了**。检查 `settings.json` 的 `skillOverrides` 是否把 `job-forge` 设成了 `off` / `user-invocable-only`。
5. **说了它不该接的话**。job-forge 只接求职相关表达；说"帮我写个 Python 脚本"它本来就不该动。

### Q2 简历生成出来是"简陋后备模板"，不是 18 套模板之一

上游 ASu 的技能按 `../../assets/` 找模板。如果 `<runtime-root>/assets` 不存在，会自动降级。

修复：

```bash
ls <runtime-root>/assets/templates-html/ | head      # 应该有 18 个 html
# 若不存在，重跑安装脚本，或手动：
ln -s asu-skills/assets <runtime-root>/assets       # macOS/Linux
```

Windows 用目录联接：`cmd /c mklink /J "%USERPROFILE%\.workbuddy\assets" "%USERPROFILE%\.workbuddy\asu-skills\assets"`

### Q3 Windows 上 `--link` 报权限错误

软链需要开发者模式或管理员权限。直接用默认的复制模式即可：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Target workbuddy -Mode copy
```

### Q4 装完发现和别的求职技能抢触发

见 [平台适配 §收敛自动入口](平台适配.md#四收敛自动入口)。核心做法：只留 `job-forge` 自动触发，其余设 `user-invocable-only`。

### Q5 支持哪些 agent？

凡支持 Agent Skills 约定（`SKILL.md` + frontmatter + `references/`）的 runtime 都能用。已实测 WorkBuddy；其余（Claude Code / Cursor / Codex / OpenCode / Gemini CLI）按公开约定路径适配，未逐一实测。清单见 [平台适配](平台适配.md)。

## 使用与效果

### Q6 它会帮我编经历吗？

不会，这是硬边界。具体表现为：

- 不编公司、职位、时间、技术栈、指标；
- 没数据 → 写"测量计划：怎么测、多久、看什么指标"；
- 团队 / 平台 / **AI 生成**的成果必须分列；
- 未合并的 PR 只能写"已提交 / 协作中"；
- 原型不能写成上线，估算不能写实测。

**为什么这么严**：AI 岗面试的第二层追问专打边界（"这块代码是你写的吗，能打开看看吗"）。编出来的东西当场崩，代价远大于少写一条。

### Q7 我完全没有 AI 项目，能用吗？

能，走"舱 C 造"：用最小可行开源贡献造一段真实经历。判断标准是**能不能讲清一个调用链**，不是 PR 数量。
刷 20 个 typo PR 抵不过 1 个讲得清的改动——面试官问两句就见分晓。

### Q8 非 AI 岗能用吗？

能。M1–M4 与岗位无关。
只有 M5 的"AI 八能力域追问矩阵"是 AI 岗专用，其他岗位跳过即可。

### Q9 它和"面试题生成器"有什么不同？

三个区别：

1. **它先判断该不该投**（M1）。市面上多数工具默认你已经选好赛道。
2. **它维护单一事实来源**（M2）。简历、口播、面经三处强制一致，不一致以证据为准。
3. **它逼你开口**（M5）。不是给你一份文档背，而是一次一问地追，追不出就判"部分验"并回炉。

### Q10 主档、账本、简历存在哪？会上传吗？

都在**你自己的工作区**，技能目录不存个人数据。除 M4 情报调研（联网搜索）与安装时拉取上游外，无外发。

`.gitignore` 已排除常见的求职文件命名（`求职主档-*.md`、`账本-*.json`、`简历-*.html` 等），避免误提交。

## 设计与贡献

### Q11 为什么不把所有能力写进一个 SKILL.md？

实测过代价：本链路 9 个 SKILL.md 合计 77 KB、references 89 KB。

- 合并后每次命中都要吃掉全部 77 KB，而 80% 场景只需要其中 1/9；
- 上游 ASu 仍在持续更新，合并即分叉，等于放弃升级；
- 无法单独关闭某一环。

所以选择**入口合并、实现不合并**：job-forge 只做路由（5–10 KB），具体活由上游技能执行。
详见 [与ASu的关系](与ASu的关系.md)。

### Q12 我能加自己的行业案例吗？

可以，见 [CONTRIBUTING](../CONTRIBUTING.md)。要求：给判定依据，不只给结论；案例里的人物/公司/数字必须虚构并标注。

### Q13 上游更新了怎么办？

```bash
# 复制模式
bash scripts/install.sh -t workbuddy
# 或软链模式（自动跟随）
bash scripts/install.sh -t workbuddy --link
```

### Q14 卸载会删我的主档和简历吗？

不会。卸载只动技能目录与上游副本，不碰你工作区里的 `.md` / `.json` / `.html` 产出。
