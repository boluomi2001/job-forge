# 使用示例

四段真实对话，覆盖四种典型处境。装好后直接说人话，不需要记技能名。

---

## 示例 1：转行前先判断方向（M1）

```
你 ❯ 我在做医学会议统筹，想转 AI 应用岗，先帮我看这个方向值不值得进

skill ❯ 好，先做四层判断。两个问题要先确认：
        ① 你瞄准的是「AI 应用/落地」还是「模型/算法」？两者利润池完全不同
        ② 有没有已经接触过的公司？我需要一个具体标的来拆第三层

你 ❯ AI 应用，落地那种。看过两家：一家做医疗知识库 SaaS，一家做 Agent 工具

skill ❯ 【第 1 层 · 表层三问】
        能不能赚钱：AI 应用层单客经济模型 = 客单价 × 续费率 −（推理成本 + 交付人力）。
        关键在推理成本随用量线性增长，而客单价常是一次性项目制 → 毛利率被两头夹。
        真正赚钱的往往不是"做应用"，是"卖订阅 + 卖实施"。要确认你面试的岗位属于哪一边。

        能不能增长：企业侧 AI 预算仍属"新增科目"，不是从既有预算里切，短期是增量；
        但要区分"试点预算"和"常态预算"——大量项目停在 POC 到生产的死亡谷。

        能不能合法做：医疗知识库涉及数据合规与院内资质，合规成本会转成销售周期，
        这会直接决定你这家公司的现金流节奏。

        【第 2 层 · 产业链】利润池在算力与云厂商 → 模型提供商 → 应用层递减。
        应用层里，能做行业交付（医疗/金融）的比通用工具更值钱，因为交付即护城河。
        ...
```

**要点**：M1 的价值不是给答案，而是给**判据**——它会把"AI 行业很火"翻译成"哪个环节赚钱、你能不能挤进去"。

## 示例 2：没经历，用 AI 对话记录挖出一段（S1 舱 A）

```
你 ❯ 我没做过 AI 项目，只有几次用 Claude 帮我写医学会议数据处理的脚本，这算经历吗

skill ❯ 先别判断"算不算"，先把事实挖出来。九段证据链，我一条条问：
        ① 当时具体要解决什么问题？（谁在痛、原来怎么做、多久做一次）
        ② 你做了什么决定？哪次是我给的方案，你自己改了什么？

你 ❯ 原来是我手动把腾讯文档导出的表格合并，一次要两小时。我让 Claude 写了个脚本按会议名合并，
        但第一版把不同场次的同名专家合并错了，我让它加了"会议日期"做联合主键才修好

skill ❯ 这就是一条真经历。按九段落地：

        【问题背景】腾讯文档导出多场次会议表，人工合并 2 小时/次，易错
        【方案决策】脚本化合并；选择"会议名 + 日期"联合主键（放弃仅用姓名，因为同名专家跨场次）
        【个人动作】定义字段映射与主键规则、逐轮修正合并逻辑、核对输出（AI 负责生成代码）
        【交付阶段】原型/技术验证（自用工具，未上线）
        【效果证据】2 小时 → 5 分钟（口径：本人单机实测，样本 3 次）；无系统化基准
        【个人边界】设计与校验是我；代码实现由 AI 生成，我审阅并修改了主键逻辑

        ⚠ 注意：不能写成"我开发了数据处理系统"——那是把 AI 的产出算成自己的。
        正确写法：设计了字段映射与去重规则，用 AI 生成脚本并迭代修正，把单次处理从 2 小时降到 5 分钟。
```

**要点**：AI 生成不等于你的实现。归属分清楚，这段经历反而更可信——面试官最反感的是"全是我做的"。

## 示例 3：明天就面（速准档）

```
你 ❯ 明天下午面一家 AI 应用公司，岗位是解决方案/AI 产品，只有两小时

skill ❯ 走速准档，跳过行业深挖和简历改造。三件事按顺序：

        【1 · 情报（3 分钟）】我搜到的面经样本：
        - 一面：产品 sense + 场景估算（"给医院做知识库，你怎么估工作量"）
        - 二面：客户沟通与需求拆解，会问"客户说不清需求怎么办"
        - 终面：老板面，关注商业判断（"你觉得我们产品最大的短板是什么"）
        来源：[小红书帖子](链接) · [牛客帖子](链接)（其中 1 条为搜索摘要，未验证原文）

        【2 · 五个高概率题 + 口播要点】
        ① 你怎么估一个医疗知识库的工作量？（考察：拆解 + 数据意识）
           口播结构：先问日活/科室数/文档量 → 拆切分与标注成本 → 给区间不给单点
        ② 客户说不清需求怎么办？（考察：需求工程）
        ③ 你和算法同学怎么分工？（考察：边界感）
        ④ 你最大的短板是什么？（考察：自认知）
        ⑤ 为什么转行？（考察：动机稳定性）

        【3 · 八条反问】已按你的目标岗位裁剪，其中三条是结构性的（会让他觉得你懂这行）
        面试前 30 分钟再看一遍即可。
```

**要点**：速准档的核心是"不改简历、不深挖行业、只练最高风险的三个点"。

## 示例 4：练一轮压力面（M5）

```
你 ❯ 练一下，按压力面来，我说的是真实项目

skill ❯ 面试契约已锁定：业务面 40 分钟 / 每题即时反馈 / 每个 Claim 最多追两层 / 压力模式。
        开始。第一题——

        你说这个脚本把 2 小时降到 5 分钟，怎么算出来的？分母是什么？

你 ❯ 我试了三次，取平均

skill ❯ 三次是同一批数据吗？数据量多大？如果换一个人用，还是 5 分钟吗？

你 ❯ ……没试过别人用，数据量大概是 200 行左右

skill ❯ 【判定】部分验
        - "5 分钟"这个数字：口径不完整（单机、本人、200 行、3 次），不能外推
        - 缺少"换人可用性"证据 → 这是被追问必崩的点

        【处置】简历里不要写"效率提升 24 倍"，改写成：
        "针对 200 行量级的会议数据，把单次合并从约 2 小时降至 5 分钟内（本人单机 3 次实测）"
        或者干脆写"消除人工合并步骤"——定性、可核验、不给你挖坑。

        下一题继续？
```

**要点**：M5 不给总分，只判 `已验 / 部分验 / 未验 / 矛盾`。答不出第二层 → 回 S1 补事实或降表述，**不许当场现编**。

## 示例 5：整条链路串起来（一站式）

```
你 ❯ 我该先做什么？目标是三个月内拿到 AI 应用岗 offer

skill ❯ 按你现在的情况（有本职工作、零 AI 项目、无目标公司），顺序是：

        第 1 周｜M1 方向闸门
          - 用四层法判断"AI 应用"里你该落在哪一环（应用交付 vs 产品 vs 平台）
          - 输出：值得进 / 只值得进某一环 / 排除
          ⚠ 这一步不过，后面全部白做

        第 2–4 周｜拿经历
          - 舱 A：把现有 AI 对话记录挖成 1–2 张证据卡
          - 舱 C：每周 5 小时，做 1 个能公开验证的小贡献（不追求数量）

        第 5–6 周｜物料
          - JD 匹配五态 → 简历改写 → 出稿（18 套模板选单栏技术版）

        第 7–10 周｜面试
          - 每投一家：情报 → 预测题 → 练一轮 → 复盘回写

        现在从第 1 周开始？我先把主档建起来。
```
